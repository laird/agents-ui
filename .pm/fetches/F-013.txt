Agent state detection
- Detection works by identifying "the foreground process and reading terminal output."
- States: "blocked — agent needs input or approval," "done — work finished and you have not looked at it yet," "working — agent is actively running," "idle — done, seen, and calm," and "unknown — plain shell or undetected."
- Workspace rollups "prefer the most urgent thing happening in that workspace."
- The heuristics are "pattern-matched against each agent's actual terminal output." [paraphrase: prompt boxes, spinners, waiting messages]
- Detection runs "on a separate async task per pane, polled every 300-500ms, decoupled from terminal rendering."
- [paraphrase] no hooks or agent-side setup are needed for built-in detection.
